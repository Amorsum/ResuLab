# 岗位定制简历：场景与价值假设

目标用户：有真实经历、需要针对不同岗位调整表达的求职者。现有字段润色可改写单段，但缺少岗位要求与候选人事实的逐项对应；新增流程将 JD、简历引用、必要追问和局部修改放在同一工作区。

用户路径：输入 JD → 核对岗位与简历证据 → 如实补充事实（允许没有做过/不清楚）→ 逐条比较原文与建议 → 确认应用 → 预览与导出。生成建议不等于写入；未经确认不改简历，版本冲突时拒绝覆盖。

价值假设：用户能更容易核实建议依据、发现证据缺口，并减少针对岗位改写的人工整理时间。当前只有合成场景与功能验证，尚无真实用户样本、耗时对照或效果统计，不将这些假设作为调研结论。

后续价值评估方案：同一合成简历/JD分别执行原字段润色与新 Agent，记录是否引用岗位、是否追问、无依据新增事实数、人工修改量和总耗时。可使用 `shared/agent.cases.ts` 的10个输入，记录模型配置、commit SHA、费用与失败。现有[新旧起草对比](results/draft-quality-comparison.json)是3组合成场景的独立起草评估，不是用户对照实验。

范围：沿用赛前编辑、模板、登录和导出能力，新增岗位优化 Agent、持久化任务、经历库和岗位工作台。现已采用 Pages / Worker / Windows Agent / Supabase 分离服务部署，公网记录见[发布验收](split-services-release.md)。当前可手动导入 JD、匹配并生成 PDF；BOSS 实站搜索/读取待验收，自动沟通与附件发送禁用，本轮未重新验收 Tauri 安装包。
