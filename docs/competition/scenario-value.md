# 岗位定制简历：场景与价值假设

目标用户：有真实经历、需要针对不同岗位调整表达的求职者。现有字段润色可改写单段，但缺少岗位要求与候选人事实的逐项对应；新增流程将 JD、简历引用、必要追问和局部修改放在同一工作区。

用户路径：输入 JD → 核对岗位与简历证据 → 如实补充事实（允许没有做过/不清楚）→ 逐条比较原文与建议 → 确认应用 → 预览与导出。生成建议不等于写入；未经确认不改简历，版本冲突时拒绝覆盖。

价值假设：用户能更容易核实建议依据、发现证据缺口，并减少针对岗位改写的人工整理时间。当前只有合成场景与功能验证，尚无真实用户样本、耗时对照或效果统计，不将这些假设作为调研结论。

对照方案：同一合成简历/JD分别执行原字段润色与新 Agent，记录是否引用岗位、是否追问、无依据新增事实数、人工修改量和总耗时。与 B 共用 `shared/agent.cases.ts` 的 10 个输入；模型配置、commit SHA、费用与失败记录齐全后再下结论。

范围：新增 Agent 交互与后端链路，沿用赛前编辑、模板、登录、云存储与 PDF 能力。本次不增加面试、语音、投递、新模板和 Tauri 打包。部署使用既有域名与本机电脑，公网入口待联调。
