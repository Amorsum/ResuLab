# 岗位表达与信息组织改进（2026-10-24）

此前验证偏重任务完成和来源有效性，没有要求建议必须改善岗位表达。旧提示词大量描述禁止项、缺少编辑方法；仅加句号也能作为一条合法修改。接口成功不代表编辑质量达标。

本次改动：

- 岗位提取明确工作职责、技术/方法、业务对象及必需要求；证据匹配选足同一经历中的相关描述和亮点，追问具体职责/做法/交付对象，不一律索要指标。
- 起草按“岗位重点→对应事实→原文问题→重组表达”执行，前置相关工作、合并重复表述、明确行动和方法。给出两个仅说明方法的改写例子，禁止挪用示例事实。
- 来源目录新增内部requirementIds供模型对齐岗位；公开协议、可改字段和引用回填保持原样。禁止挪用其他经历的事实，不把参与升级为主导，不把JD或否定回答变成个人能力。
- 避免机械扩写或重复填入描述、亮点和自我评价；没有指标仍可改善职责和方法表述，不能强制编造STAR结果。
- stage-3在原事实/数字校验后拦截仅标点、空格、分行、列表拆分的建议（cosmetic_only_change）。这与JSON/语义修复共用一次额度，不增加任务调用预算；stage-4再次检查。修复不能绕过数字、类型、目标、before或来源规则。

该确定性检查只识别纯格式变化，不证明语义真实性，也不能检测所有低价值同义改写；最终仍需用户核对。它保留单词顺序和技术符号，不把真正的信息重排、C++/C#或版本号变化归为标点变更。

## 验证

后端类型检查、构建及41项测试通过，包含纯格式识别、真实内容重排、技术符号、一次质量重写成功/失败，以及质量重写后编造90%被原数字校验拒绝且不再重试。失败尝试仍计入调用数和用量。

最终[新旧真实模型对比](results/draft-quality-comparison.json)使用同一份合成经历分别投后端、数据运营和缺Redis经验的岗位。基线为864935c，实际模型deepseek-flash；这是独立起草评估，不使用真实人员数据，不写数据库、不创建账号，不代替完整HTTP流程。

| 场景 | 基线表现 | 新版实际输出 |
| --- | --- | --- |
| 后端岗位 | 合并部分接口事实 | 接口开发、筛选分页、前端协作、日志排查前置，日常事务后置，保留参与和同事定方案的边界 |
| 数据运营岗位 | 理由声称前置，但正文仍先写TypeScript接口 | 正文和亮点实际前置SQL渠道汇总、Excel去重、周报；不补转化率成果 |
| 缺少Redis经验 | 主要补全“参与开发”的对象 | 重组已有TypeScript接口职责，不把Redis或性能优化写成经验，保留参与边界 |

三个新版结果均含2项非空建议，通过既有事实规则及纯格式检查；后端场景首次夹带一项纯格式修改，被拒绝后在同一次修复中改为实质表达。该轮共7次真实模型请求（基线3、新版4），按配置费率估算0.042148 CNY，并非实际账单或稳定平均成本。早一轮候选仍有重复扩写，收紧提示后才取得本报告；两轮合计15次独立起草调用。小样本人工对比不代表总体提升率，描述与亮点仍可能重复。

脚本：`server/scripts/verify-draft-quality.mjs`。必须显式提供候选目录、服务器配置路径、旧版目录和报告路径；密钥不放命令行。后续完整HTTPS/Auth/模型回归单独记录。
