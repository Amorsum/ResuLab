# 可靠性和限制

创建任务先事务入库，再返回202。创建按用户串行化并用(owner,scope,key)唯一约束幂等；回答/重试锁住所属任务，再验证状态、幂等键和输入摘要。相同键不同内容409；回答需覆盖当前所有问题且ID唯一。不同账号统一404。每用户未结束任务/UTC每日新任务有上限。

每完成一步保存视图和stage，开始步骤也记录running和attempt。模型调用先原子预留一条记录并检查总预算，再发送请求。默认每任务6次，修复、重试和进程重启均不重置。人工重试最多3次。

| 故障 | 行为与本地验证 |
|---|---|
| 模型超时 | AbortController覆盖连接和读取；持久化MODEL_TIMEOUT，可手动从当前步骤重试 |
| 429/5xx/连接失败 | 默认最多1次退避重试；全部计入预算；非暂时性4xx不重试 |
| 非法JSON/schema | 最多1次修复，仍失败记录MODEL_SCHEMA_INVALID |
| 非法来源/目标/数字 | 拒绝保存未经验证建议，记录TOOL_RESULT_INVALID |
| 重复创建/回答/重试 | 同键返回原操作响应，不再次推进；查询获取最新状态 |
| 浏览器刷新 | 服务器任务不变；A保存runId后查询恢复 |
| API进程退出/失联 | 停止续租，90秒过期后可重新领取当前stage；未完成步骤可能重新执行 |
| 旧执行者返回 | 租约token和有效期双检查，禁止提交过期结果 |
| 数据库暂不可用 | 返回脱敏503；不能写检查点时保留旧检查点，等租约恢复 |
| 预算耗尽 | BUDGET_EXHAUSTED且不可重试，停止后续模型调用 |

本地验证实际执行迁移SQL（PGlite PostgreSQL WASM）、HTTP接口、模拟上游超时和数据库关闭重开。重开测试在同一测试进程中重建数据库实例并人工推进租约过期，不能替代真实Supabase上的有状态API进程重启验收。补充真实Supabase验证：两个临时账号登录、真实并发创建/回答/重试的幂等、跨账号隔离、RPC授权和租约/检查点均通过；记录见results/supabase-acceptance.json。测试租约由fixture仅注入自己创建的任务，未执行全局领取；模型和队列的真实多进程竞争、进程检查点恢复与网络故障仍待DeepSeek配置后验收。

人工介入：先查看所属任务error/steps及服务端仅含requestId/runId/code的日志；恢复配置/上游后，通过retry接口重试可恢复失败，不直接改状态。如果预算已耗尽需明确告知用户，不能假称重试不收费。没有自动取消接口，等待回答的废弃任务需由授权管理员按保留策略清理。

外部模型执行不能保证exactly-once。若模型已计费但响应尚未保存时进程退出，记录保持started、用量未知；恢复可能再次请求。数据库结果提交和用户操作幂等，不能消除此计费窗口。次数是发送前预留数，极端中断下可能尚未真正发送；用量未知不填0。

生产没有启用可控provider/故障注入的配置入口；测试通过依赖注入使用stub。默认日志不打印简历、JD、Authorization、API key或上游错误体。模型日志仅保存配置、时间、状态、上游request ID和用量。仍须对数据库备份、用户数据保留期限和访问权限按实际部署管理。
