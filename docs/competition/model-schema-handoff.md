用户报告：步骤“查找简历证据”失败，轨迹提示“模型返回结构不符合约定”，估计费用显示“未知”。尚未获得该任务的原始模型结果和具体校验问题，因此不能声称已确定具体字段或已修复模型链路。

## 已定位的代码

- `server/src/provider.ts`：`schema.parse(JSON.parse(content))` 的 catch 会将 JSON 解析失败和 Zod 结构错误统一映射为 `MODEL_SCHEMA_INVALID`。自动修复最多一次，目前只补充“修复 JSON 结构和必需字段”，没有携带具体错误路径。
- `server/src/engine.ts`：证据匹配调用 `matchingSchema`；需要 `tool=find_resume_evidence`，`result.evidence` 与 `result.questions` 数组，证据中的 coverage、refs 对象和追问字段必须满足共享 schema。
- `shared/agent.schema.ts`：结构通过后仍需 engine 的引用/事实验证，不应为了绕过错误放宽来源检查或凭空补全经历。

## 费用未知单独核对

后端仅在该次调用同时具备 `prompt_tokens`、`completion_tokens` 和两个单价参数时计算费用：

```text
MODEL_INPUT_PRICE_PER_MILLION
MODEL_OUTPUT_PRICE_PER_MILLION
MODEL_CURRENCY
```

按实际模型和已确认的计价口径填写；本文件不假定模型型号、价格或缓存命中价格。当前聚合逻辑在任一调用费用或 Token 不完整时保持 null，前端按协议显示未知。结构错误本身不必然导致费用未知，也不能把失败调用当作免费。

云端现有部署配置位于 `C:\ResuLab\config\server.env`（以实际部署为准）。补充计价配置后需重启 API；旧任务已有的未知费用不会自动重新计价。
