# 项目材料与简历体验升级

初轮真实模型合成验收完成理解、成稿、局部重写三次调用，无修复请求；模拟和真实模型报告分开记录。GitHub 公开样例已实际完成仓库元数据、默认分支、固定提交归档下载和文件解析，平台限流时提示上传 ZIP。公开 Gitee 测试中元数据/分支接口成功，匿名归档下载返回401；Gitee 继续提示使用 ZIP。

ResuLab 源码样例的真实模型验收通过：两次分块理解、一次成稿、一次局部重写，共5次模型请求（成稿首次结构错误后修复1次），生成18条可定位证据；浏览器完成入库、PDF/Word 导出和版本操作。身份及个人贡献均为合成数据，不代表真实账号验收。

“我的简历”可导出/预览导入独立文档备份（20 MB、最多200份）；恢复重新映射基础/岗位身份，保留历史并清除云端关联，避免覆盖现有文档。经历来源标记保留为待核验信息，跨账号恢复后不会仅凭旧来源身份判定为重复。

自动浏览器验收：`npm run test:project:browser` 使用独立 PGlite、合成身份与模拟模型，截图和结果在 `.cache/project-workspace`。显式添加 `-- --real-model` 会沿用本机模型配置、消耗真实模型额度，但仍只用合成身份和材料，不读取真实用户经历或远端数据库。

添加 `--resulab-fixture` 使用本仓库 README、依赖说明、简历类型、状态更新与导出源码作为第二组材料；个人贡献仍使用明确标注的合成角色，不认定这些源码都由真实用户完成。该组结果放在 `.cache/project-workspace/resulab`。

成稿提示将未确认的成果和责任边界作为生成约束，避免把“未主张某项成果”写成简历贡献。用户自行输入的改写要求不会自动成为项目事实。

编辑中的空标题或空贡献仍可保存为草稿；确认入库时才要求完整标题、至少一条非空贡献，且简述和贡献合计不超过现有简历字段的4000字限制。用户可增删贡献；校验失败保留本机输入并允许修正后继续保存。
求职工作台沿用经历库明确保存的本次选材；选材损坏、超过上限或引用已归档/待同步经历时要求重新核对，不回退为全部经历。没有选材记录时才使用全部已确认经历。
刷新后如本机草稿基准仍有效，将自动继续上传；基准冲突时保留草稿并提供另存项目入口。

公开仓库读取验收：在 server 目录运行 `node --import tsx scripts/verify-project-repositories.ts`。只读取两个公开测试仓库，结果写入 `.cache/project-workspace/repositories.json`，不访问私有仓库、模型或数据库。Gitee 仍需以实际结果为准，不因适配器存在就声明可靠可用。

导出前检查显示实际预览页数、姓名/联系方式缺失、缺少描述与横向溢出，可返回对应表单修改，也可确认继续导出。智能一页的字号、行距和页边距作为一个撤销动作提交。

`ResumeDocumentsPage` 接管 `/my-resumes`，访客也可管理本机文档。兼容读取旧经历副本和旧备份；本地后端版本单独标明仅此电脑。云简历仍主动同步，更新按既有 updated_at 条件匹配，冲突展示本机/云端对照。迟到保存仅确认云端版本戳，不替换用户正在编辑的正文。

简历文档元数据由 `shared/resumeDocument.ts` 定义，本机索引位于独立 IndexedDB `resulab-resume-documents`，按账号隔离。文档采用乐观版本检查，显式切换或恢复时才创建历史检查点（最多30份），正常保存不生成无限备份。旧简历保留为未分类，不推断父子关系。

切换文档或账号会清空当前内存撤销链，避免跨文档恢复；云端保存确认仅更新 ID/版本戳，撤销正文时保留该同步基准。刷新前的未完成本机修改保留原版本基准，冲突时可“另存当前稿副本”恢复编辑，不覆盖别的页面的新版本。

本机文档读、版本检查和写入在同一 IndexedDB 事务完成。每个浏览器标签页保存自己的恢复快照及其原版本基准，刷新时不会把其他标签页较新的版本号套到旧内容上。

项目草稿冲突时同样可以另存为独立项目会话，原会话保持原样；不将冲突草稿自动确认为事实。选择文件变化后旧理解标记过期，重新分析后才能确认采用。模型完成也推进会话版本，防止旧页面覆盖新结果。

本轮分阶段实现项目材料工作区、统一简历管理与导出检查，仅用于本地运行，不自动执行远端迁移或发布。

确认经历与会话版本更新使用同一数据库事务；网络重试复用幂等响应，避免经历已保存而界面状态未更新时重复追加。

项目材料协议在 `shared/project.ts`。材料解析依赖服务端 `fflate`，仅读取文本，不执行项目代码。单个归档 50 MiB、解压 200 MiB、10,000 项；分析预算 72,000 字符，超出时需要调整选材。

一次分析最多选择200个文件；72,000字符预算包含文件路径和 JSON 转义开销。默认选中预算内的文件，全部候选和选中状态可见；超限时必须调整选材，不会静默截断。

实现及验收进展以本文件后续记录为准；模型模拟测试不代表真实模型质量验收。

项目理解按原文分块并校验文件路径、行号和连续引文。写作同时读取这些证据与用户回答；已有岗位写作现在也携带所选条目的原始记录和结构字段，新增事实仍须人工确认。

失败或主动停止后重新分析时，若材料快照、选材和已有回答未改变，将复用已完成且通过原文校验的分块；材料导入重试以输入摘要和幂等键识别，避免重复创建或重复读取仓库。

每个账号最多保留20份未删除的材料（包括上传成功但尚未创建会话的材料）。停止读取后的暂存操作不会在刷新时自动继续，用户可主动重新选择同一材料恢复。
已读取但尚未创建会话的材料会在项目工作区列出，可继续整理或删除。

模型提供的引文必须逐字存在于当前输入片段，服务端从原文计算行号；同一引文出现多处时仅在模型给出的行号能唯一对应时采用，否则要求重新生成。分块保留开头及连续空行，避免行号偏移。

接口前缀 `/api/career/projects`：`materials/upload` 接收 ZIP 二进制（Idempotency-Key 请求头），`materials/repository` 接收公开根链接；`sessions` 创建/列出任务，`sessions/:id` 读取/修改草稿；`analyze`、`draft`、`rewrite` 入队；`cancel` 撤销执行权，`confirm` 确认入库。所有操作按账号隔离；修改携带 expectedRevision 和幂等键。ZIP 仅在受限内存中解析，不保存原始归档；保留筛选文本。删除材料同时清除会话引文、任务分块和幂等响应中的原文。

本地迁移位于 `server/migrations/project-workspace.sql`，由 `dev:career` 启动时应用。材料和会话进入独立 PGlite；模型任务复用 Agent 队列、调用预算和租约，通过同一事务保存检查点。取消撤销租约，旧执行器不能迟到写入。其他启动方式不自动变更数据库。
