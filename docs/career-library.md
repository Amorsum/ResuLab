# 经历库 v2

经历与简历文案分开保存：`CareerEntry` 保存原始材料和已确认事实，版本不可变；岗位选材属于任务，应用计划属于目标简历。`ResumeData.careerOrigins` 保存逐条来源，旧简历不需要此字段。

手动应用通过 `APPLY_CAREER` 一次提交并记录一次撤销。应用前核对目标简历完整快照，重复来源默认跳过，替换需要明确指定目标。创建独立版本保留个人信息与排版，清除旧云简历 ID。

云端由现有 Node Agent 服务提供 `/api/career/entries`（GET/POST）、`/entries/:id`（PATCH）、`/entries/:id/revisions`（GET）、`/runs`（GET/POST）、`/runs/:id`（GET）、`/runs/:id/{selection,retry,cancel,supplements}`（POST）、`/validate-sources`（POST）、`/versions`（GET/POST）、`/versions/:id`（GET）和 `/versions/import`（POST）。沿用 Supabase Bearer token，不需要模型配置即可管理经历和保存手动岗位版本。导入岗位副本不会将其转换为事实。

新增迁移 `supabase/migrations/202610260001_career_library.sql`，依赖此前 Agent 与 legacy_web 两项迁移，新增条目及不可变版本，给现有队列增加 `career_tailor` 类型和上下文。两类任务共用并发、租约和模型预算；选材推荐检查点为 awaiting_input，确认后才进入写作。取消通过终止状态和撤销租约阻止迟到提交。旧 Agent 路由拒绝操作新类型任务。

服务角色 RPC 显式校验 owner，浏览器仅可通过 RLS 读取本人条目和历史版本；写入只走认证后端。提交携带 expectedRevision，冲突返回 409。来源检查同时核对确认状态和版本。`confirm` 是独立的人工确认意图，普通编辑保存不会保留已确认状态。

本地测试通过不代表生产数据库迁移或发布完成。

## 本地运行（当前交付方式）

原 Agent 服务器关机时，从根目录执行 `npm run dev:career`，前端为 `http://127.0.0.1:3010/library`，API 为 `http://127.0.0.1:8788`。不会连接原 Agent、部署线上应用或修改远端 Supabase 数据表。端口可用 `CAREER_WEB_PORT` / `CAREER_API_PORT` 覆盖；不要复用正被其他程序占用的端口。

后端在 `server/.local-agent` 创建独立 PGlite，并自动执行本地迁移；数据跨重启保留。登录沿用根 `.env` / `.env.local` 的 Supabase 公开配置，以真实会话校验身份，不需要服务角色密钥。模型可在 gitignore 的 `server/.env` 填写 MODEL_BASE_URL / MODEL_API_KEY / MODEL_ID；缺模型时明确返回 CONFIG_MISSING，经历管理、手动选材和岗位版本仍可用。可选出站代理沿用 server 配置，不打印配置值。

此模式前端明确显示“本地后端”，岗位版本也保存在该本地数据库，并从经历库版本列表打开；不会冒充已跨设备同步，也不会把本地版本 ID 当成 Supabase 云简历 ID。原有云简历入口仍是独立功能。需要完整本地旧 AI 服务时继续使用 `npm run dev:upgrade`，前提见其配置说明。

本地后端仍需联网验证 Supabase 会话。Windows 未显式配置 HTTP_PROXY / HTTPS_PROXY 时，本地启动脚本读取已启用的系统 HTTP 代理，仅供当前 Node 进程出站使用；localhost 始终默认绕过代理，不修改系统设置或生产代理行为。登录验证限定 10 秒，网络中断、限流或认证服务故障返回 AUTH_UNAVAILABLE / 503；只有明确无效会话返回 UNAUTHENTICATED / 401。前后端配置或代理变更后需重启本地后端。

`npm run test:career:browser` 使用独立浏览器、合成账号与接口，不访问外部服务，不调用真实模型。脚本单独构建合成配置的前端并以 preview 提供测试页面，明确启用本地开发提示，避免依赖开发服务器的依赖预构建缓存。截图与结果输出到忽略的 `.cache/career-workspace`；失败会保留页面截图、HTML 与未完成请求。

配置真实模型后，可在 server 目录显式运行 `node --import tsx scripts/career-live-preview.ts --synthetic-only`，访问 3198 端口进行真实模型验收：前端与 Node API、PGlite、队列和模型调用均为实际实现，仅身份使用本次进程生成的合成会话，所有经历必须使用合成材料。该工具不访问远程 Supabase 数据，也不更改 3010 的用户经历。验收期间 GET `http://127.0.0.1:3197/api/e2e/report` 将本次隔离数据及用量写入 `.cache/career-live/report.json`；模型 Key 不返回前端或报告。不要将此测试入口作为正常服务发布。

验收入口从 server 目录启动时，PostCSS 显式定位仓库 Tailwind 配置，内容扫描也相对配置文件解析，避免不同启动目录导致模板样式遗漏。

本次用户已在本机配置模型，API 报告 modelConfigured=true、模型名 deepseek-flash，并通过真实模型请求验收。用户原有远程 Agent 服务器没有启动、连接或更新。

岗位选材区显示“Agent 模型”状态及“模型配置说明”，直接读取后端 health 中的配置状态；未配置或状态读取失败时禁用 Agent 推荐，手动选材仍可用。此处不是可任意选择的模型目录：当前由后端统一配置一个模型。health 仅返回配置布尔值和可显示的模型名称，不返回 API Key 或服务地址；配置就绪仍需实际请求验证网络与模型能力。

`dev:career` 监听 `server/.env`：保存配置后通过 IPC 优雅关闭旧后端、保留数据库并启动新进程，前端保持运行；配置无效时前端继续显示连接问题，修正保存后可重试。请点击“刷新模型状态”读取更新；不会自动调用模型或消耗额度。配置模板不预填 API Key；实际凭据仅保存在被 Git 忽略的本机配置文件。

## 客户端与兼容

`CareerWorkspacePage` 接管 `/library`，沿用现有视觉和组件样式。录入包含快速草稿、完整表单和可编辑的提取事实；技能等级必须人工选择。Agent 任务轮询串行且按账号隔离，任务 ID 留在本机，最近任务列表可在其他设备恢复。

新建和编辑使用视口内的对话框，桌面居中、手机全屏；关闭或按 Escape 后返回入口。编辑草稿按账号和经历分别保存在本机，重新打开时恢复；若原经历版本已变化，保留草稿原有版本基准并提示，保存时仍会执行冲突检查。

“从当前简历拆分导入”的预览紧邻按钮显示并自动聚焦，确认后才保存。没有实际经历时显示空态及编辑入口，不允许确认空导入；只有默认学历、技能等级或生成 ID 的空白表单行会跳过。当前简历仅指当前浏览器、当前站点地址的编辑器内容，基本信息不拆成经历。

Agent 仅在 queued/running 轮询，等待用户确认、完成和失败后停止；可手动刷新任务状态。大经历库可将候选范围缩小到搜索 / 分类筛选结果或已勾选经历，锁定项始终保留，超过 160 条事实时提示缩小范围而不静默截断。

`careerStore` 用独立 IndexedDB `resulab-career-v2` 缓存云端记录和待上传队列，不升级或清除旧库。保存先落本机再提交后端，冲突保留两份内容并暂停自动重试。同步按钮可重试网络失败；用户查看差异后可将本机内容作为新草稿提交。

备份格式升级到 v2，包含条目与本地岗位副本，同时支持 v1 导入预览。旧材料按来源与原条目 ID 派生稳定 UUID；重复迁移跳过。外部备份一律恢复为待确认，AI 改写和岗位副本不升级为事实。旧岗位副本通过确定 ID 的 insert-ignore 导入已有云简历表，避免重复迁移覆盖用户后来编辑的版本。

求职工作台使用 `readUnifiedLibrary` 读取已同步的 v2 事实，无 v2 条目时兼容旧库。原 Worker 匹配、生成和批量审核协议保持不变。

真实模型验收使用隔离的合成账号、竞赛经历和 PGlite：推荐调用 1197/370 输入/输出 Token，用户确认后写作调用 1718/217 Token，共两次成功调用，无修复调用。锁定项目保留、排除奖项未入选，缺少线上增长经验明确显示缺口；竞赛身份与职责边界保留。实际验证整批填入、同源默认跳过、一次撤销、独立岗位版本保存和重新进入经历库恢复结果。独立版本包含一条项目和一条来源，原事实仍为版本 1。实际点击导出 PDF 和 Word，PDF 为一页 A4，经渲染检查排版正常；Word 正文回读包含对应经历且无解析警告。报告和合成文件位于忽略的 `.cache/career-live`。

实机定位到 Node 直连认证服务 ECONNRESET、沿用系统代理后 settings 接口返回 200。重启本地后端后，用明确无效的合成凭证验证认证服务可达，返回预期 401；没有读取用户浏览器凭证，也没有因此宣称用户待同步条目已经上传。恢复网络后同一会话可重试同步，测试验证本机内容保留且成功后清除 pending。

当前实机本地 API health 为 databaseConfigured=true、modelConfigured=true。上述真实模型验收使用合成身份，不等于真实账号全链路或线上跨设备同步验收。本轮没有修改远端 Supabase 数据库或关机服务器。

待上传条目会区分版本冲突与其他上传失败，保留本机内容并提供核对或同步重试入口。
